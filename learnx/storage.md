# learnx 存储规则

**原则：能连 Notion 就存 Notion，否则存本地；本地数据在下次能连 Notion 时提示同步。**

## 一、判断 Notion 是否可用

本会话第一次需要读写数据时判断一次，结果在本会话内沿用：

1. 可用的 MCP 服务器里有 Notion（名字通常含 `notion`），先列出它的工具；
2. 用 fetch 读取下面的"learnx 学习数据"页面；
3. 读取成功 → Notion 模式；任一步失败 → 本地模式，并告诉我"Notion 不可用，本次写入本地"。

会话中途 Notion 调用失败：重试一次，仍失败就切到本地模式并告诉我。

使用要点：
- 写入数据库前先 fetch 对应的 data source，以实际 schema 为准（我可能在 Notion 里改过字段）。下面的字段表只是参考。
- 查询优先用 `rows` 模式加过滤条件，或 fetch 数据库视图；**不要依赖 SQL 模式**，非商业版有工作区级的配额限制。
- 属性只放用于筛选和排序的字段；卡片和日志的正文按 `templates/` 下的模板写进页面内容。
- 日期属性要拆成 `date:<字段>:start` 和 `date:<字段>:is_datetime`（0）。

### 字段参考

**学习计划**：名称（标题）、类型（阶段 / 周计划 / 项目迭代 / 深挖专题 / 地基补课）、状态（未开始 / 进行中 / 已完成 / 搁置）、时间范围（日期，可为区间）、目标、完成标准、对应矛盾/节点、触发方式（项目触发 / 地图触发 / 兴趣探索）、复盘。

**问题卡片**：概念（标题）、对应矛盾/节点、类型（可推导 / 可选择 / 跳跃）、知识类型（地图知识 / 工作知识 / 基础功）、掌握度（初次理解 / 能复述 / 能预测 / 能重建）、来源、创建日期、当前间隔（天）、下次重建、重建次数、引出的新问题、产生模式（teach / read / code / replay / review / locate / project）。

**工程日志**：标题、日期、项目（Kvwall，可新增选项）、对应矛盾/节点、现象、指标变化、状态（调查中 / 已解决 / 搁置 / 假设被否定）。

**材料清单**：名称（标题）、作者/来源、类型（书 / 论文 / 工程博客 / 设计文档 / RFC/PR/issue / 源码 / 事故复盘 / 课程/演讲）、层次（多选：操作系统 / IO 与存储 / 网络与 RDMA / GPU 编程 / 推理系统 / KV Cache / 分布式）、知识类型、状态（未读 / 通读中 / 已通读 / 精读中 / 已精读 / 已重建）、链接、备注、对应矛盾/节点、精读重点。

## 三、本地位置

根目录：`~/learnx-data/`（Windows 上是 `%USERPROFILE%\learnx-data\`）。不存在就创建。

```
learnx-data/
├── plans/        计划，一个文件一条：YYYY-MM-DD-<名称>.md
├── cards/        问题卡片：YYYY-MM-DD-<概念>.md
├── logs/         工程日志：YYYY-MM-DD-<标题>.md
├── materials.md  材料清单（一张 Markdown 表，列与 Notion 相同）
├── pending-sync.md  尚未同步到 Notion 的条目清单
└── replay/       replay 模式的里程碑（含答案，我不该打开）；无论 Notion 是否可用都存这里，不同步
```

- 每个文件开头用 YAML frontmatter 写属性，字段名与 Notion 相同；正文按模板写。
- 文件名里的非法字符（`/ \ : * ? " < > |`）替换成 `-`。
- 每在本地新建或修改一条，就在 `pending-sync.md` 追加一行：`- [ ] <类型> <文件相对路径> <新建/修改> <日期>`。

## 四、同步

- 进入 learnx 且 Notion 可用时，如果 `pending-sync.md` 里有未勾选的条目，告诉我条数并问是否现在同步。
- 同步时逐条写入 Notion（先按标题查重，已存在就更新，不要重复创建），成功一条勾选一条。本地文件保留，不删除。

## 五、读取顺序

需要读数据（例如 rebuild 抽题、plan 查进度）时：Notion 模式读 Notion；如果本地 `pending-sync.md` 还有未同步条目，也一并读本地，避免漏掉。本地模式只读本地，并提醒我结果可能不全。
