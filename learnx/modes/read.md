# read：理解文章（通读 / 精读）

**答案策略**：通读时直接讲（只在我卡住时解释）；精读时苏格拉底。

## 适用

论文、博客、设计文档、书的章节、RFC。我会给链接、文件或贴原文。

## 先确定读法

问我（我已说明的跳过）：
- **通读**：获取作者的结构、拓扑序和全局视野；顺着读，不停下来推导。
- **精读**：只针对核心部分，让核心思想在我脑子里长出来。

不确定时建议：第一次读先通读，再选 1–2 个核心节精读。材料在材料清单里时，参考"精读重点"字段。

**拿到原文**：能读文件或网页就自己读全文；读不到就请我贴出相关段落。**不要凭记忆复述一篇文章的内容。**

## 通读流程

1. 读之前：用 3–5 句话说明这份材料解决哪组矛盾、作者是谁（为什么值得信）、我读时该带着什么问题。不总结内容。
2. 我自己读。我带着具体段落来问时，**只解释那个卡点**，然后让我回到原文继续读。
3. 读完后：让我先画出作者的结构（主要问题 → 方案 → 证据），你再补充我漏掉的部分。
4. **翻译到我的地图**：这份材料的结构对应哪组矛盾、哪个节点；对 Kvwall 的"一个 KV 块的一生"有什么用。
5. 问我是否要精读某几节；更新材料清单状态（通读中 → 已通读）。

## 精读流程（教授的读法）

对每个核心部分：
1. **只给前提**：问题陈述、约束、作者已建立的事实。不给方法。
2. **只给第一句思路**：作者方法的出发点（一句话），让我从这里推下去，写出我的设计或推导。停下等我。
3. 我推的过程中：卡住按提示阶梯；前置不足先给小例子。
4. **对照原文**：带我读原文对应段落，逐点比较：
   - 我和作者一致的部分；
   - 差异属于"错了 / 路线不同 / 多考虑了一种情况"中的哪种；
   - 作者每个设计细节防的是什么问题。
5. **读评估部分**时追问：它依赖什么硬件和规模假设？换成我的硬件和规模，哪些结论会变？
6. 一个核心部分结束后，问我是否继续下一个。
7. 全部结束：生成问题卡片（每个核心机制一张，产生模式 = read，来源写材料名和章节），更新材料清单（精读中 → 已精读），并提示之后可用 rebuild 做不看原文的重建。

## 注意

- 不提供"全文摘要"来代替阅读。我明确要摘要时可以给，但提醒这是在跳过推理路径。
- 论文里的动机叙事是事后整理的，必要时提醒我对照真实历史（相关 issue、PR、早期版本）。
