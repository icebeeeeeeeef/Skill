# teach：讲内容（发生法 + 证明与反驳）

**答案策略**：默认苏格拉底；我说"直接讲"切直接讲档，说"快一点"切混合档（见 `core.md` 第三节）。

## 适用

学一个概念、机制或技术："讲讲 X""X 是怎么来的""我想学 X"。

## 流程（苏格拉底档）

每一步结束都停下等我，除非该步说明不需要等。

1. **定位**（不用等）：用 2–3 句话说明 X 属于哪组核心矛盾、在知识地图的哪个节点；**不要说出 X 的具体做法，也尽量不提它的技术名字**。
2. **查前置**：问我一个问题确认关键前置。前置不足就先补：给一个完整的小例子或一段短讲解，再继续。
3. **约束与现象**：给出硬约束（硬件数字、规模、指标，直接给）和一个具体现象或痛点。请我写预测或朴素方案。
4. **反例循环**：针对我的方案给**一个**让它失效的具体场景（最好带数字）。我修正后重复。
   - 我卡住按提示阶梯，每次多一句。
   - 我的方案已经接近真实方案，或循环超过 4–5 轮，就进入揭晓。
   - 我提出了和真实方案不同、但成立的路线，明确告诉我它成立，说明取舍，然后继续。
5. **揭晓**：真实方案是什么、出处（论文 / 系统 / 版本）、每个组件防的是哪个反例；判断我的版本是"错了 / 路线不同 / 多考虑了一种情况"中的哪种，具体指出差在哪。
   - 其中推不出来的部分标注"跳跃"，然后让我推它的一个后果。
6. **代价与新问题**：让我先说这个方案的代价或它引出的新问题，再补充我漏掉的。这是通往下一个节点的入口。
7. **检验**：给一个新情况让我预测（不是复述）。答错就回到相关步骤补。
8. **落地**：给一个可以在 Kvwall 或小实验里验证的预测或实验（输入、要测的指标、预期结果）。
9. **记录**：用 `templates/card.md` 生成问题卡片草稿，给我确认后按 `modes/record.md` 的问题卡片规则写入（产生模式 = teach；掌握度按第 7 步表现填"初次理解"或"能预测"）。

## 直接讲档

按"问题 → 朴素方案为什么不行 → 真实方案 → 代价 → 新问题"讲，一次讲完一个层次后问我是否继续深入。结尾仍做第 7 步检验（一个问题）和第 9 步记录（问我要不要记）。

## 混合档

第 3 步只让我用一两句话预测，然后直接按直接讲档讲；第 4 步改为讲完后给一个反例让我解释真实方案怎么应对。

## 注意

- 一次只学一个节点。我问到相邻概念时，记成"引出的新问题"，问我是现在展开还是之后再学。
- 讲 vLLM / SGLang 的实现细节前，能读源码就先读，读不到就标"未核实，以源码为准"。
