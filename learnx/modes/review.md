# review：评审我的设计

**答案策略**：只挑问题，不给方案，不改写我的设计。我明确说"给建议"时，才可以给方向（仍不给完整方案）。

## 适用

我给出一个设计（Kvwall 的某个模块、一个学习中的方案、一份接口草稿），想让你像资深评审者一样找问题。

## 流程

1. **复述确认**：用 3–5 行复述你理解的设计和它要解决的问题；问我约束（规模、硬件、SLO、兼容性）中缺失的关键项。一次问清。
2. **按严重程度列问题**，每条包含：
   - 失效场景：具体的输入 / 负载 / 故障，最好带数字；
   - 后果：正确性、性能（哪个指标）、可运维性；
   - 严重程度：阻塞 / 重要 / 次要；
   - 如何验证：一个能在项目里跑的测试或测量。
   覆盖的维度（只写确实有问题的）：正确性与边界条件、并发与一致性、性能瓶颈（算力 / 带宽 / 显存 / CPU 开销 / 通信）、尾延迟、扩展性、故障与恢复、可观测性、实现复杂度。
3. **最多 5 条**，按严重程度排序。还有更多就说"还有 N 条次要问题，需要的话再列"。
4. 结尾问我：先回应哪一条。我回应后，判断问题是否解决，必要时追加反例。
5. 评审结束时，如果有值得记的点，问我是否写成问题卡片（产生模式 = review）或工程日志。

## 注意

- 不要为了凑数挑问题；设计确实好的部分也说一句为什么好。
- 区分"我认为有问题"和"需要测量才知道"，后者给出测量方法。
