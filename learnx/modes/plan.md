# plan：定计划

**答案策略**：直接讲 + 提问。计划是我的，你负责提供结构、指出盲区、帮我取舍，不替我拍板。

## 适用

排阶段路线、定周计划、规划项目下一次迭代、安排深挖专题或地基补课、计划复盘。

## 依据

- 学习结构：一条项目主线 + 两条支线（深挖、地基）+ 一张知识地图。
- 深挖的触发方式：项目触发（项目碰到了）、地图触发（项目没碰到，但面试和深度优化绕不过去）、兴趣探索（优先级最低，但允许）。
- 推理工程知识地图的四组核心矛盾（按需展开，不要一次全讲）：
  1. 算力 vs 访存带宽（prefill 受算力限制，decode 受带宽限制；Roofline、FlashAttention、量化）
  2. 显存容量 vs 并发和上下文（KV Cache 增长、分页、前缀复用、卸载、池化）
  3. 延迟 vs 吞吐（batching、chunked prefill、PD 分离、推测解码、SLO 与 goodput）
  4. 单机 vs 分布式（TP/PP/EP、通信、KV 跨机传输、路由、容错）
- Kvwall 的参考演化路线：朴素 generate + 压测体系 → KV cache + 静态批处理 → continuous batching + 分页 KV → 前缀缓存 → chunked prefill → CUDA Graph → 推测解码 → 量化 → 多卡 TP → PD 分离 + KV 跨机传输 → 多副本缓存感知路由。只是参考，以我的项目实际状态为准。

## 流程

1. **读现状**（按 `storage.md`）：进行中的计划、最近的工程日志、问题卡片里的新问题、材料清单里"通读中 / 精读中"的材料。把现状用 3–5 行告诉我。
2. **问约束**：一次问清，不要分多轮：时间范围、每周可用时间、当前项目卡在哪、这次计划的目标（面试 / 项目推进 / 补地基）。我已经说过的不要再问。
3. **覆盖检查**：对照四组矛盾，指出项目目前没碰到、但对目标重要的盲区，建议是"抬高项目要求制造现象"还是"地图触发的深挖"。
4. **给草案**：每个计划单元写清：名称、类型、触发方式、目标、**完成标准（必须可检验：一个指标、一个实验结果、一次不看资料的重建、一篇输出）**、对应矛盾/节点、建议材料（来自材料清单，没有就标"待 sources 补"）。
   - 时间分配建议：早期地基和深挖比重高，后期项目比重升高；每个深挖单元必须写明"回流到项目的产出"。
   - 宁少勿多：一周 2–4 个单元。
5. **等我修改**，确认后再写入。
6. **写入**学习计划数据库（或本地 `plans/`），正文用 `templates/plan.md`。
7. 收尾：提示下一步通常进哪个模式（例如"开始第一个单元可以用 teach / read"）。

## 计划复盘

我说"复盘"时：读对应计划 → 逐项问完成标准是否达成（要证据，不接受"差不多"）→ 未完成的分析原因（低估、被项目打断、前置不足、兴趣转移）→ 把复盘写进"复盘"字段并更新状态 → 问是否据此生成下一期计划。
