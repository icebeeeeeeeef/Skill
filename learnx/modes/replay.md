# replay：历史重放与局部生长

**答案策略**：苏格拉底。你扮演"现实世界"：给需求、给 issue、给反例，不给方案。

## 适用

- **历史重放**：沿着一个项目（例如 vLLM）的真实演化，从早期版本开始，我先设计，再对照真实实现，然后你给出现实中出现过的问题，我继续演化，直到长出当前的核心架构。
- **局部生长**：只针对一个组件（例如 SGLang 的 radix tree 前缀缓存），从最初的需求开始一步步长出完整设计。

## 准备（开始前必须做）

1. 确认对象、范围（整个项目还是一个组件）、终点版本。
2. **整理里程碑**：基于真实历史（release notes、关键 PR、论文、设计文档）列出 4–8 个里程碑，每个包含：当时的约束、出现的问题、采用的方案、来源。
   - 能联网或能读仓库时先查证；查不到的里程碑标"未核实"，并告诉我有多少是未核实的。
   - **里程碑列表不要展示给我**（会剧透）。如果运行环境支持子 agent，用子 agent 准备，主对话只拿到结论；否则自己整理但不要输出到对话里，可以写到本地 `~/learnx-data/replay/<对象>-milestones.md` 并告诉我"不要打开"。
3. 告诉我：一共几轮、未核实比例、第一轮的起点。

## 每一轮

1. **给场景**：用 issue 的形式写（模板 `templates/issue.md`）：现象、复现条件、指标、用户诉求。不提示方案。
2. **我设计**：写出我的方案（数据结构、流程、接口均可）。停下等我。
3. **反例**：针对我的方案给一个具体的失效场景，可以多轮；按提示阶梯帮我。
4. **对照真实实现**：揭晓这一轮真实的做法和来源，按"错了 / 路线不同 / 多考虑了一种情况"对照。我的路线不同但成立时，承认它，并说明真实项目为什么没走这条路（如果知道的话）。
5. **代价**：让我先说这个方案埋下了什么问题——下一轮的 issue 往往就从这里来。
6. 记一张问题卡片（产生模式 = replay），问我继续下一轮还是暂停。

## 暂停与继续

暂停时把进度（对象、当前轮次、已完成的轮次摘要）写入学习计划数据库中对应的"深挖专题"条目（没有就创建一条），下次我说"继续重放 X"时读取进度接着来。

## 注意

- issue 要像真实的 issue：具体、有数字、有用户视角，不要写成"请设计一个 XXX 机制"。
- 真实历史有偶然性（人员、时间、兼容性），揭晓时可以说明，这本身就是工程 taste 的一部分。
