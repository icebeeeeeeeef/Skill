# record：问题卡片与工程日志

**答案策略**：直接执行，但内容要来自我。卡片里"我的朴素方案""我和正式方案的差异"等字段必须是我的真实想法，不要替我编。

## 适用

- 记一张问题卡片（学完一个机制后）；
- 写一条工程日志（项目里的一次优化、一个问题的调查）；
- 整理今天学的内容。

## 问题卡片

1. 确定概念。如果是本会话里刚学的，从对话中提取各字段的草稿；不是的话，按模板逐项问我（一次问 2–3 项，不要一项一轮）。
2. 用 `templates/card.md` 生成草稿。缺我本人的内容（朴素方案、差异）就留空并问我，**不要编造**。
3. 给我确认。确认后按 `storage.md` 写入：
   - 属性：概念、对应矛盾/节点、类型、知识类型、掌握度、来源、创建日期 = 今天、当前间隔（天）= 1、下次重建 = 今天 + 1 天、重建次数 = 0、引出的新问题、产生模式。
   - 正文：卡片模板内容。
4. 写入前按概念查重：已有同名卡片时，问我是更新还是新建。

## 工程日志

1. 用 `templates/log.md` 逐项收集。重点追问：
   - **测量证据**：没有数据的"感觉变快了"不接受，至少给出测量方法和数字；还没测就把状态设为"调查中"；
   - **考虑过的方案及取舍**：至少两个方案；
   - **假设是否被证实**：被否定的假设同样要记，状态设为"假设被否定"，这类日志很有价值。
2. 确认后写入：属性（标题、日期、项目、对应矛盾/节点、现象、指标变化、状态），正文为模板内容。
3. 日志中学到的新机制，问我是否顺手生成问题卡片（产生模式 = project）。

## 整理今天学的

回顾本会话（或我提供的内容），列出值得记录的条目（每条一句话 + 建议记成卡片还是日志），让我勾选，然后逐条按上面的流程处理。
