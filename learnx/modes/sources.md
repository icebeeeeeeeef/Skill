# sources：找资料、选资料

**答案策略**：直接讲。但推荐必须有理由，且标明哪些信息未核实。

## 适用

为某个主题找材料、判断一份材料值不值得读、决定通读还是精读、维护材料清单。

## 材料分工（选材时按需求匹配）

| 材料 | 最擅长 | 主要风险 |
|---|---|---|
| 教材、经典书 | 结构、拓扑序、地基 | 流畅错觉；部分过时 |
| 论文 | 问题、设计、评估（发生史） | 动机是事后整理的；结论依赖硬件和规模 |
| 工程博客 | 挣扎过程、真实数字、踩坑 | 质量参差；过时快 |
| RFC / PR / issue 讨论 | 取舍过程、被否决的方案 | 零散，需要背景 |
| 源码 | 当前的事实 | 弯路已被抹掉 |
| 事故复盘 | 反例 | 场景不一定相同 |
| AI（你自己） | 针对卡点解释、陪练 | 拓扑序弱；快速变化的细节常错 |

## 选材原则

1. 作者是否亲身做过这件事（系统作者、维护者、一线工程师优先）。
2. 有没有真实数字和评估。
3. 有没有讲"为什么不是别的方案"。
4. 时效：快速变化的主题优先近期材料和源码；原理类优先经典。
5. 宁少而深：每层一两份骨架材料足够。

## 流程

1. 问清（我已说明的跳过）：主题、目的（建地图 / 解决项目问题 / 面试深挖 / 补地基）、对应的三类知识（地图知识 / 工作知识 / 基础功）。
2. **先查材料清单**，已有的材料优先推荐，避免重复收集。
3. 推荐 1–3 份（不要列长书单）。每份写：名称、作者/来源、类型、为什么适合这个目的、建议**通读还是精读**、精读哪几节、对应矛盾/节点。
   - 能联网时，搜索并确认标题、作者、年份和链接；不能联网或没确认的，标"**未核实**"，链接留空，绝不编造 URL。
4. 判断"值不值得读"时：按选材原则逐条给结论，最后给一句建议（读 / 精读某几节 / 只用 locate 模式快速定位 / 不读）。
5. 我同意后，写入材料清单（先按名称查重；已有就更新状态和备注）。
6. 收尾：提示可以用 read 模式开始读，或用 locate 先快速定位。
