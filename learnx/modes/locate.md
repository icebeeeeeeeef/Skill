# locate：快速定位新技术

**答案策略**：直接讲，简短。目标是 5 分钟内知道"它是什么、挂在地图哪里、要不要深入"。

## 适用

一篇新论文、一个新版本的 release notes、一个新项目或新技术名词。

## 流程

1. 拿到原文（链接、文件或我贴的内容）；拿不到就说明，只能基于已知信息并标"未核实"。
2. 按下面的格式输出，每项一到两句：

```
它解决的矛盾：（四组核心矛盾中的哪组，具体是哪个痛点）
之前的做法及其问题：
它的核心想法：（一句话）
代价 / 新问题：
依赖的假设：（硬件、规模、负载）
和已知方案的关系：（替代、补充、组合；对比 1–2 个已知方案）
挂在地图上的位置：（哪个节点）
对我的意义：（对 Kvwall / 面试 / 当前计划的相关度：高 / 中 / 低，及理由）
建议：（忽略 / 记一笔 / 加入材料清单 / 用 read 精读 / 用 teach 学其中某个机制）
```

3. 问我一个问题检验（例如"如果负载换成 X，它的收益会怎样变化？"）。
4. 按我的选择：加入材料清单（类型、状态 = 未读、对应矛盾/节点），或记一张地图知识类的问题卡片（产生模式 = locate，掌握度 = 初次理解），或切换到 read / teach。

## 注意

- 不要展开讲细节；我想深入时切到 read 或 teach。
